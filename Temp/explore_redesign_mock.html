Motion design (emil-design-eng tokens)

Three principles applied: No animation on frequent actions (card press = instant scale). Spring on rare actions (filter dropdown open). prefers-reduced-motion respected globally (all transitions collapse to 0.01ms).

Impeccable craft-floor audit

Rules enforced in this mock (no exceptions):
  • ✓ No gradient text — hero headline uses solid cream on forest
  • ✓ No glassmorphism decoration — search bar has a subtle box-shadow, no backdrop-blur on cards
  • ✓ No emoji icons — footer buttons use text labels only (real build uses Lucide SVG)
  • ✓ Themed browser surfaces — dropdown arrow uses inline SVG, no system-default carets
  • ✓ Contrast checked — ₦1,500 price (#0F2A1D on #fffdf8) = 12.4:1 (AAA)
  • ✓ prefers-reduced-motion — global media query collapses all transitions
  • ✓ Button press = scale(0.94–0.97) — cards, pills, filter chips all give tactile feedback
  • ✓ No category pills above grid — the overcrowding is removed; categories live ONLY in the dropdown inside Filters
  • ✓ Grid starts at the same scroll position on mobile + desktop — no geometry drift between breakpoints
What changes between A and B:
  • Removed: the 18-pill category row that sits above the listing grid on both mobile and desktop
  • Kept: the category dropdown inside Filters.tsx (desktop sidebar) and inside the mobile bottom-sheet
  • Result: on mobile, listings start ~240px down (hero ends + dropdown height) instead of ~420px (hero + 18 pills + dropdown)
  • Result: on desktop, the redundant pill row is gone — the sidebar dropdown is the single entry point

One question before I commit:

When you open the category dropdown in Filters, should it show the currently-selected category pre-highlighted (preserves context when you reopen), or should it always reset to "All categories"? I defaulted to "All categories" in this mock because that's the current behavior, but your "filters should respect choices" rule suggests pre-selecting.
