## Approach

### Data boundary (use interfaces as-is)
- Add `packages/data/src/explore.ts` (NEW): `ExploreListing = Listing & { rating?; verified?; featured?;
  soldOut?; availability?: 'open'|'closed'|'soon'; categorySlug?; image?; vendorName?; trending?: boolean }`.
  A `loadExplore(opts)` boundary calls `mockListingsRepo` + `mockVendorsRepo` + `mockSearchRepo`, maps to
  `ExploreListing[]`, applies filter/sort/paginate, returns `{status, data, error, cached}`.
- Extend `packages/data/src/mock.ts` (NOT interfaces): `MOCK_EXPLORE_LISTINGS` (~12, clearly labeled mock,
  some with `images:[]` to exercise missing-image monogram, one `soldOut`, varied rating/verified/
  featured/category), `MOCK_VENDORS`. Wire `mockListingsRepo.list({campus?, category?})` to return filtered
  mock; `mockSearchRepo.search(q)` to substring-match title; add `mockListingsRepoThatFails` (throws) for
  the error/retry e2e path (selected via `?exploreError=1`, dev/test-only, never in prod path).
- Filter/sort logic lives as PURE functions in `explore.ts` (unit-testable): `applyFilters`, `applySort`,
  `paginate`.

### Routes (no Landing touch)
- `apps/web/app/explore/page.tsx` (NEW, server) → renders `<Explore />`.
- `apps/web/app/c/[categorySlug]/page.tsx` (NEW, server) → `<Explore categoryPreset={params.categorySlugts} />`.
  Same component, category preset from URL + shown in heading (PG-PUB-003 route variant, not duplicate page).

### Components (`apps/web/components/explore/`)
- `Explore.tsx` (client): owns filter/sort/search state (synced to URL params for shareability), uses
  `useExploreData` hook, renders campus indicator, SearchBar, Filters, result grid (ListingCard), TrendingRail,
  RecentlyViewedRail, and all states. On mount, runs the D.4.1 continuity entrance.
- `ListingCard.tsx`: C.3.1 Compact/Editorial hybrid — imagery-led frame (B.6: 4:3, matte, overlay),
  title (h3/body), price as TABULAR data (always legible), availability chip, trust row (verified badge /
  rating / featured mark), missing-image → contour monogram, sold-out → struck/muted, loading → shimmer in
  frame. Click records to recently-viewed (client-only, documented).
- `Filters.tsx`: category select, price min/max, min rating, verified-only, featured toggles, sort select.
  Desktop = persistent sidebar; mobile = bottom sheet (fixed drawer, token-only, no framework).
- `SearchBar.tsx`: debounced (250ms) input, updates URL `q`.
- `TrendingRail.tsx`: horizontal scroll of `trending` listings (from mock flag).
- `RecentlyViewedRail.tsx`: client-side deduped list (localStorage/state; clearly client-only, not backend).
- `ExploreSkeleton.tsx`: skeleton grid + rail skeletons (B.6 shimmer in frame).
- `ContourEdge` at whisper intensity in Explore header (B.12: contour drops to whisper/structural).

### Primitive enhancement (justified, minimal)
- `packages/contour/src/ContourEdge.tsx`: add optional `intensity?: 'structural'|'whisper'|'strong'`
  (default 'structural'); Explore passes 'whisper'. Same forward-`...rest` discipline already on ActivityNode/
  Surface/Type.

### Landing→Explore transition (D.4.1 replacement note)
- Component (1) Contour-carry (PRIMARY): Explore entrance animates the contour edge growing in
  (`view-transition-name` on contour element) — the contour language continues from Landing. TRUE shared-
  element morph across the route is partially limited because Landing files are OUT OF SCOPE (cannot set
  `view-transition-name` on Landing's node). Implemented as an Explore-side entrance that carries the
  contour motif; documented as a known limitation of the no-touch-Landing constraint.
- Component (2) Shared spatial anchor (PRIMARY): a consistent top bar with the Voeq wordmark at the SAME
  vertical position as Landing's heading → stable reference across the boundary.
- Component (3) Deep transient accent (UNPROVEN, OPTIONAL): a brief deep-green flash on the contour line
  mid-entrance via a transient CSS class. ATTEMPTED; if it reads as a glitch in browser inspection, CUT it
  (not shipped). Evidence will state kept/cut + why.
- Mechanism: View Transitions API (`document.startViewTransition`) with 600–900ms first / 320ms subsequent,
  single directional move, NOT hard cut / NOT fade-to-white. Feature-detected; falls back to a plain 320ms
  directional move when unsupported. Filters apply uses 120–320ms meaningful transition (D.2/D.4).

### Required states (all built, all tested)
- Empty: `data` length 0 for campus → "No vendors yet on {campus}" + CTAs (browse other campuses / become a
  vendor). Triggered by `?campus=nowhere` (zero-match) — a REAL zero-results case, not just pre-load.
- Loading: skeleton grid + rail skeletons.
- Error: `?exploreError=1` → `mockListingsRepoThatFails` throws → retry affordance; cached last-good shown
  if present; partial results + "some content couldn't load" + retry. NEVER fake success.

### Responsive (LOCKED)
- Mobile (375px): single-column scroll, filters in bottom sheet.
- Desktop (1280px): multi-column grid (3–4 col), persistent filter sidebar.

### Density tier (B.12)
- Explore = Editorial tier: ~0.9 spacing multiplier vs Landing's 1.0 (use tighter spacing tokens), contour
  whisper, Cream surface (default). No env change needed.
